Время загрузки контекста исполнителем, подготовки/локального ревью и ожидаемых небольших исправлений распределено по этим строкам. Отдельный второй бюджет проверки поверх таблицы не добавляется. Модельная очередь, OCR для сканов и неуказанные тарифы не маскируются под время кода: скан без текста получает понятную ошибку, OCR в первый объём не входит. Большие CV/медленный provider могут добавить внешнее ожидание, которое будет названо отдельно. Наиболее неопределённы извлечение фактов и совместимость старых данных; верхняя граница не повод запускать неоговорённую дополнительную работу.

Что уже переиспользуется и уменьшает объём: PDF/plain-text чтение, конфигурация нескольких sources/exports, снимки CandidateContext, история feedback, текущий scoring, работающий Vite. Чего нет и что включено в таблицу: upload API/UI, корректное чтение DOCX, редактируемые typed fields/skills, document→structured facts, профильная интеграция scoring. Импорт текста и семантическое извлечение фактов — разные работы.

После веб-поиска проверены готовые варианты (подробности и источники в comments.md): Mammoth `extractRawText` для DOCX, Godocx как Go-native альтернатива, React Hook Form+Zod resolver для редакторов, необязательный react-dropzone для выбора файлов. Предложение — использовать готовые библиотеки, не писать собственный DOCX parser/универсальный form engine. Документация/лицензии проверены, но пакеты не установлены и не проверены на наших CV; конкретный вариант/версию закрепить при реализации. Для PDF сохранить pdftotext. Диапазон30–50мин относится ко всему контуру документов, а не к сложности вызова DOCX-библиотеки; извлечение фактов остаётся отдельным шагом.

Полный новый scoring engine/арифметика вкладов, Overview вакансии, сбор/поисковые переключатели, автоматическая генерация поиска из профиля, генерация/отправка CV и слияние всего DESIGN-2 в эту таблицу не входят. ## Acceptance criteria — приёмка

Политика тестов уточнена владельцем: только немного критических targeted-проверок скрытых ошибок, которые он НЕ способен обнаружить глазами в приложении. Для Profile это прежде всего атомарность профиль+история при сбое Save, защита ручного изменения от позднего анализа/устаревшей revision и отсутствие неожиданного LLM-запуска при сохранении. Выбрать минимальные нужные проверки по фактическому изменению и переиспользовать имеющиеся; не писать тест на каждый field/component или всю матрицу вариантов. Внешний вид, кнопки, обычные Save/Cancel и отрисовку проверить в браузере. Общие suites по умолчанию SKIPPED; результат точечного critical test отмечать отдельно.

- Поддерживаемый документ реально читается; по нему доступны факты с происхождением либо честное состояние ошибки/неизвлечённости. Несколько CV питают один профиль. Пользовательский ввод и исходные документы не теряются.
- Навыки, целевые роли, компенсация, engagement/hours/work mode, география/relocation/право на работу, языки/доступность и свободные ограничения редактируются с валидацией, Save/Cancel и устойчивым к ошибке черновиком. Неизвестное сохраняется как неизвестное.
- Подтверждённое ручное исправление не перетирается очередным импортом; истинные конфликты видимы, Paris/Lisbon не считаются одним полем. Пока конфликт не разрешён, UI и scoring одинаково отражают неизвестность.
- Сохранённый навык/целевая роль меняют текущий быстрый результат на подготовленном примере с полным описанием; вычисление использует сохранённую версию профиля. На этом этапе нет обещания, что произвольный travel-текст уже учтён быстрым алгоритмом или что готовы все объяснения из Overview.
- Обновлённый профиль используется подробной оценкой при явном её запуске; сохранение формы не запускает массовые LLM-запросы. Старая оценка отмечается stale по версии профиля, не только текста вакансии.
- Экран доступен на staging и пригоден для работы Claude Design: настоящие props/состояния/API вместо демонстрационных данных. Разметка отделена от обработки запросов и состояния.
- Сборки и реальный браузерный сценарий записаны; точечные критические скрытые инварианты проверены при необходимости, общие suites SKIPPED. Не изменять production, не выпускать/сливать без отдельного итогового решения владельца.
