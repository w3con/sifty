# Sift — local job triage, Part 1

A private, loopback-only React catalogue, TypeScript CLI and stdio MCP server over the same SQLite store. It collects public vacancies, preserves their available descriptions and provenance, assesses fit and prepares editable application drafts against versioned candidate evidence. **No employer form-filling, uploads or submission tools exist.**

## Stage 2 — inspect and prepare, owner reviews

In **Pre-selected**, open the inline **Application** tab. First opening prepares only a genuinely new draft with no prior operations; revisiting an existing, failed or cancelled draft never regenerates automatically. **Application is disabled in Triage**, with a visible explanation. Archive can review stored drafts but cannot prepare. The primary action acknowledges clicks immediately with Starting, then shows preparation/sign-in/retry/review states. An old login-only successful operation with zero fields is not presented as prepared answers. Provider/model selection, reinspection and other technical actions live under **More actions**. Preparation is independent of collection and the assessment switch, uses configured **openai / openai/gpt-6.1-sol** by default, and offers configured alternatives without fallback or routing changes.

The separate persistent `.local/sessions/application-inspection/` profile is for application inspection, not collectors or the owner's regular browser. **Sign in to continue** lets the owner establish a login; closing that login page resumes inspection and drafting within the same operation. The startup page is reused, so a leftover blank window does not keep the operation running. Sift does not type credentials. Automated inspection validates public destinations, paces document reads and blocks all non-GET/HEAD requests and downloads/service workers. It reads rendered labels, types, available choices, requirements, lengths, attachment constraints, accessible frames and shadow roots, excluding navigation/search/footer controls. It follows supported read-only Apply navigation; it never presses submit/next, fills controls or uploads. Password/login gates are not application questions.

Collector transport behavior is unchanged; its response metadata now additionally exposes content type/security headers for this caller. True downloads/404/access responses become actionable coverage states, with bounded read/redirect handling.

That page's **Apply now buttons** use its exact Getro currentJob.url, not an anchor: `https://www.linkedin.com/jobs/view/senior-smart-contract-engineer-at-aave-labs-4477571659`. If access remains gated, add questions manually. Existing answers remain intact on failed reads; no model is invoked for an unreadable questionnaire.

User-facing errors, including old saved failed operations, strip ANSI/Playwright call logs and show concise actions. Full technical response/navigation records are saved incrementally under ignored `.local/application-inspections/`; worker failures retain raw details under `.local/application-preparation-errors/<operation-id>.json`. Main redirects are validated and explicitly re-navigated in the same session, rather than letting browser redirect interception gaps reach unvalidated addresses. Redirected supporting resources/embedded frames that cannot be followed safely remain explicit coverage gaps. No fills, uploads, submission, forged authentication or forwarded session cookies are part of public recovery.

* `GET /api/jobs/:id/application`: saved draft and latest operation history.
* `POST /api/jobs/:id/application/prepare`: async HTTP 202 with `{inspect,generate,provider,fieldId?,login?}`. Requires Pre-selected; active requests for the role are deduplicated. Default provider is `openai`.
* `POST /api/jobs/:id/application/cancel`: cancels queued work or aborts the owning server's running browser/provider. Saved answers remain intact.
* `PATCH /api/jobs/:id/application`: `{fieldId,revision,value}` or `{revision,selectedFile}`; updates draft/revisions only.
* `POST /api/jobs/:id/application/questions`: manual `{label,type,options}` with distinct manual provenance.
* `POST /api/jobs/:id/application/remember`: `{fieldId,revision,scope,confirmed:true}`; only explicit confirmation writes reusable knowledge.
* `GET /api/jobs/:id/application/memories`: applicable scoped knowledge.
* `GET /api/application-files/cv.pdf` or `/profile.pdf`: exact whitelisted existing PDF preview.

All routes retain loopback/Host/Origin/JSON protections. Cancellation closes only the operation-owned browser context and terminates the owned provider process group (or aborts the local HTTP provider); it prevents late snapshot/answer writes and releases the shared inference slot after child termination. Cancelled work remains distinct from failed work and dead-owner **interrupted** work. Cancelled operations retain ownership until cleanup completes, preventing another worker opening the same profile early. A different process's live work must be cancelled through its owning server; it is never killed by an unrelated instance. Queued owner requests resume after restart; interrupted work requires explicit retry. Preparation does not hold the collection lock or change the assessment On/Off preference. Generation waits for the shared inference slot. Request guards and epoch/sequence checks reject duplicate starts and stale UI responses.

MCP adds `application_prepare`, `application_cancel`, `application_draft`, `application_update`, `application_question`, `application_memories` and explicitly confirmed `application_remember`, using the same storage/services. No browser action/submission tools are exposed. Stage 3 remains future work: filling approved values, uploading selected files, final authorization, submission and verified external success.

## Sift workflow (current approved stage)

The dark neutral interface follows the supplied **Jobs Workflow** design: Triage / Pre-selected / Archive, independent list/detail scrolling, default Fit assessment, local list filters, a Settings drawer and a live queue bar. IBM Plex Sans/Mono and Unbounded remain self-hosted. Narrow screens stack scrollable list and detail without removing essential controls. The pinned Queue/Paused-details button opens failures/retry information and Configuration even when the status bar scrolls horizontally.

* **Triage:** Select (Y) moves a role to Pre-selected; Dismiss (N) rejects it. Both decisions stay in the current tab's Triage list until reload, with a check or struck-through title. These session sets are memory-only. A decision selects the next visible undecided role, wrapping around; Undo returns a decided role to Triage. Dismiss is retained rejection, never permanent deletion.
* **Pre-selected:** Back to triage reverses selection. **Apply** opens the validated employer URL (original-listing fallback) in a new tab directly from the user gesture, with its opener severed. It does not read a form, invoke a model, fill anything or submit. The app then asks **“Did you submit your application?”** Only **“Yes, applied”** persists Applied and a server timestamp. Not yet, Escape, scrim dismissal and popup blocking leave Pre-selected. **Confirm application…** supports confirming later without reopening the external page. The confirmation stays bound to its original role even if a concurrent CLI change alters the list.
* **Archive:** Shows the real owner-confirmed application date, preserving the internal `applied` stage/API. Undo returns the role to Pre-selected and clears that date. Opening a listing is never evidence of submission. The vacancy, draft and application history are permanently removed after thirty elapsed days from valid `appliedAt`.

Opening a role persistently records its first seen timestamp independently of stage and assessment fingerprints. Header counts are global stage totals; the former “roles · by fit of…” sentence is removed. Search stays in the header. The toolbar above the list contains **Unread**, **Filters** and **Best fit / Newest**. Unread uses durable seen state and retains a newly opened unread role until another role is chosen, so it does not vanish while being read. Viewed rows use darker subtitles beneath the title; unread rows retain brighter typography, without dot indicators. Best fit sorts descending with unassessed last; Newest uses first-collected time, not publication or last refresh. Choices persist locally. Quick filters retain Web3, Remote, 75+ and Hide expired and add **Management title**, bounded CTO/Chief Technology Officer/Head/Director/Manager/Lead matching that excludes lead generation. This is a title filter, not an assertion about responsibilities. Queue polling rejects pre-write snapshots and keeps review, provider selection and typed feedback intact.

### Permanent deletion and retention

**Delete role…** is available outside Triage and opens a compact role/company-named in-app confirmation, explaining that deletion cannot be undone. It is separate from Dismiss. `DELETE /api/jobs/:id` requires JSON `{confirmed:true}` and uses the same Store deletion service as automatic retention. Both remove the job, sightings, snapshots, assessments, queue entry, feedback database links, workflow, drafts, revisions, questionnaire snapshots, preparation operations and incoming alias chains in one SQLite transaction. Referenced inspection/error logs are removed after the database transaction; any filesystem failure is returned and logged rather than claimed successful. Cached discovery inventories drop matching listings. Explicitly remembered Markdown knowledge, shared CV/context/configuration and the dedicated owner login profile are independent and retained.

The server and MCP runtime check retention at startup and every minute. Only `applied` entries with valid actual UTC confirmation timestamps at least 30×24 hours old are eligible. Missing, invalid, impossible, future or legacy undated values are not inferred; Triage and Pre-selected are never age-purged. Work claimed by a running preparation/assessment or cancelled preparation still cleaning up blocks deletion. Live collection/inference slots also postpone it to avoid asynchronous enrichment/provider-probe races. Manual Delete explains the active-work reason; automatic retention skips and retries next minute. Queued operations can be removed transactionally without being started. Explicit assessment Off is never changed.

Technical tombstones retain **SHA-256 URL hashes only**, with no descriptions, answers or role text. Automatic `Store.upsert` returns **0** when an incoming original or employer URL matches a deleted listing's known current/historical URLs, including snapshots and merged sightings; collection callers skip that sentinel rather than enqueueing a nonexistent job. A genuinely different opening with the same company/title and different original **and** employer vacancy URLs can be collected normally. An alternate source reusing a deleted employer URL remains suppressed. Company/title identity hashes are neither created nor consulted for deletion suppression. **An explicit manual URL import intentionally restores** matching incoming URL hashes and creates a new Triage record with a new monotonically increasing ID, not the previous draft/history. Deleted IDs and alias IDs are never reused after restart. A Git pull does not clear tombstones. Old external SQLite backups are independent copies and must be managed separately by the owner.

Keyboard: **J/K or arrows** navigate, **Y/N** decide an undecided Triage role, **A** opens Apply from Pre-selected, **/** focuses search, **Escape** blurs search/closes filters or the current modal. Shortcuts ignore input/select/textarea, nested contenteditable elements, composing/modifier keys and open dialogs. Settings and confirmation trap focus and restore it on close.

### Shared workflow storage / compatibility

Schema v8 adds nullable `seen_at` and `applied_at` columns and append-only `workflow_history`; it does not rewrite legacy records or assessments. HTTP/CLI/MCP return canonical `stage` (`triage`, `preselected`, `no`, `applied`), `seen`, `seenAt`, `appliedAt` and content-derived `isWeb3`. Physical `status` keeps `new/saved/rejected` for compatibility, plus `applied`. Lists/updates accept either canonical stages or the old aliases (`shortlist` also maps to Pre-selected). Collection refresh and late dedup preserve seen, applications, aliases, evidence and histories.

`PATCH /api/jobs/:id` accepts `{ "stage": "preselected" }` or legacy `{ "status": "saved" }`. Applied additionally requires the role to be Pre-selected and literal `{ "stage": "applied", "confirmed": true }`. `POST /api/jobs/:id/seen` records a first open; GET/detail/list never marks seen implicitly. CLI uses the same store, e.g. `status ID preselected`, or owner-confirmed `status ID applied --confirmed`; `list applied` returns the same date as the UI. Existing MCP list/detail tools expose these fields and aliases; no workflow-mutation or employer-submission tool was added.

**Stage 2** is implemented above for read-only inspection and editable drafts. **Stage 3** remains outline-only: filling approved answers/files and submitting after final explicit authorization, with Applied recorded only on confirmed site success. The existing external Apply and manual confirmation remain unchanged.

### Assess vacancies switch

The bottom status bar's **Assess vacancies** switch controls the persistent assessment worker. It defaults **On** only when no explicit preference exists. Both On and Off are saved in SQLite `queue_state` under `assessment_enabled`, separately from transient provider errors/retries. The choice survives browser reload and server restart, and is shared by every tab. It does not edit model/provider configuration.

**Off** prevents new queued inference, including priority Reassess and Save-and-reassess requests; these requests can still enqueue pending work. An already-running inference finishes, and the queue is retained. The worker checks the choice before acquiring work and again after its asynchronous availability probe, so switching off during that probe prevents a launch. **On** resumes eligible work on the next worker tick without resetting provider or per-job backoff. Collection continues independently. Explicit provider smoke checks and direct CLI/MCP assessment commands remain separate owner-triggered operations, not queued worker execution.

`GET /api/queue` returns authoritative boolean `enabled`. The loopback/Host/Origin/JSON-protected `PUT /api/queue/assessment` accepts only a boolean `enabled` and returns the updated queue. The UI waits for that response, disables only during saving, displays save failures next to the control, and rejects stale polling snapshots across a save. It shows Off / current-inference-finishing separately from provider pause. The switch stays outside the horizontally scrollable queue metrics at desktop, 390px and 320px, with native Space activation and an accessible switch name/state.

## Part 1 refinements

**Catalogue filters** expose configured **Roles / Skills** tag clouds through the existing filter-options endpoint. Every tag is enabled initially; all-on is unrestricted, a subset matches OR within the group, groups combine with AND, and all-off means **no matches**. Roles retain title aliases; Skills use available title/tags/description. Sources and assessment retain the old empty-is-unrestricted checkbox semantics. Local preference version 2 migrates legacy empty role/skill lists to unrestricted and preserves saved subsets, legacy terms, source/assessment and quick filters. Reset is reachable in an empty list and clears query/filter/sort choices without rewriting collection settings. Missing descriptions make skill exclusions uncertain.

**Discovery caching** stores source inventories/fingerprints in jobs.sqlite and individual listing/query responses in ignored `.local/network.sqlite`. Listing TTL is three hours. Finite public inventories are re-filtered locally when terms change; query/category requests reuse exact URL/body/network-profile fingerprints, so unchanged requests are reused and additions fetch only uncached keys. Removed terms require no additional network requests. Preferences, model and candidate edits schedule reassessment, not collection. Repeating a cached search can continue missing detail enrichment. Every title is eligible for missing descriptions, including keyword-only matches outside technical titles. Available/deferred/failed descriptions and current-run fetch attempts are separate from listing exhaustion. Existing historical Braintrust receipts are displayed as incomplete when descriptions remain missing; they are not rewritten to claim new fetches.

Descriptions have an independent **24-hour cache**, with ETag / Last-Modified conditional revalidation and retained bodies on 304. Failed detail attempts defer for an hour; other missing details can progress in subsequent cached searches. An explicit API `POST /api/search` with `{ "source": "Braintrust", "force": true }` bypasses listing TTL only (use the exact configured source name); it never bypasses pacing/cooldowns. Public search POST is still limited to the verified Getro and Algolia read-only endpoint shapes. No employer action endpoint is exposed.

**Traffic discipline** is shared by actual destination hostname, including Getro API requests from multiple source aliases and browser fetches. At most one request per domain runs; a persisted cross-process lease and a 3–6 second gap after completion protect the next request. Retry-After is honoured; transient failures use exponential backoff, and 403/CAPTCHA stops the domain for 24 hours. The cooldown and next-request time survive restart in network.sqlite; restarting/forcing collection does not reset them. Ordinary 404/410 does not stop an unrelated role on the same domain. Different domains remain independent. Browser collection permits only read-only requests and paces eligible document/script/fetch resources; unsupported/blocked browser workflows remain explicit.

**Automatic assessment** is a durable queue in jobs.sqlite, resumed by the running catalogue server. Jobs enqueue as listing pages/details become available, independently of the collection lock. There is one inference worker, no ten-per-run ceiling, persistent retries/backoff, selected-role priority and immediate HTTP 202 enqueue responses. UI shows running/pending/failed/current/missing-description counts, elapsed time and actual errors. Missing descriptions are not labelled as inference pending. Fresh completed input fingerprints are skipped; actual candidate/preferences/prompt/model/description changes requeue work. The server notices changed local candidate files without refreshing remote profiles. Keep the server running to drain the queue; a CLI daily collection can enqueue work but does not leave an untracked background process after exiting.

**Routing/runtime:** extraction and assessment now use **`luna` (`openai/gpt-6-luna`) through the existing OpenCode subscription login**. This model ID was verified with `opencode models`, structured smoke inference, a genuine Kraken assessment and the running background queue on 2026-10-30. This is an explicitly configured small-model route, not a fallback. Local inference remains selectable, but no local runtime is installed/listening on this laptop and its placeholder model must be replaced with an installed ID before selecting it. Unavailable providers pause the queue with a visible reason. Claude is configured for `haiku` but is not logged in. Sol remains an explicit alternative; strong-model form answers and letters remain Part 2. No runtime download, global configuration change or API-key billing fallback was introduced.

**Candidate feedback** is Part 1 evidence, not employer-form drafting. One text field plus **Save and reassess** is the confirmation. The original text is immediately saved verbatim in an additive English record under `kb/Applications/candidate-feedback/`, with date, source job URL/title, owner-click provenance, general/role scope and conflict notes. No model is needed to preserve the statement. Conservative optional deterministic extraction recognises explicit skill absences/experience and relocation preferences; anything else remains attributed raw evidence. Extraction never invents missing facts. Conflicts retain earlier statements and require review; **Edit as new revision** appends a linked revision and marks the old wording historical in assessment context. Role-scoped feedback is excluded from other roles. General feedback invalidates dependent assessments safely, without re-downloading vacancies. The UI shows exactly what was saved and the file path. Records are not automatically committed; `kb/faq.md`, generated indices and builder-owned `ai:` metadata are untouched.

New assessments separate **confirmed mismatches**, **unknown candidate facts/questions** and **unknown employer details**. A missing CV mention is unknown, never confirmed absence. Older `gaps` are read compatibly as unknown questions, never migrated to asserted mismatches. Exact candidate evidence IDs/quotes and content-derived provenance validation remain required.

## Start on the laptop or mini

Run from the repository root (resolve it with `git rev-parse --show-toplevel`). Node **22.13+** with `node:sqlite`, npm, Git and Poppler's `pdftotext` are required. Node 26.5.0 was used for verification. On macOS, install the missing prerequisites explicitly with Homebrew (`brew install node poppler`).

```sh
npm --prefix app ci
npm --prefix app run build
npm --prefix app run cli -- validate
npm --prefix app run cli -- context --refresh
npm --prefix app run cli -- search
npm --prefix app run cli -- list
npm --prefix app run cli -- assess 11
npm --prefix app start
```

Replace `11` with an ID from `list`. Open **http://127.0.0.1:4317**. The server binds only to `127.0.0.1`; Host/Origin checks reject other origins, and mutations require JSON. No public listener or active scheduler is installed by dependency installation or server startup. Stop with Ctrl-C. Rebuild after UI changes. The existing personal `site/` is independent.

In **Settings → Sources**, use **Collect jobs** or a source's **Search source** to collect/resume cached discovery; **Assess role / Reassess** prioritises the selected role in the persistent queue. Select/Dismiss/Undo persist immediately. Descriptions are rendered as text, never executable source HTML. Missing employer links are explicitly warned about; Apply then opens the original listing for manual review. Low fit and inference failures do not automatically reject roles. Rejected records remain available through CLI/MCP `list no` (or `list rejected`).

## Editable inputs

Settings edits the actual `config/*.yaml`, validating before writing and backing up the prior bytes under `.local/`. Editing files in your editor also works. Existing source names, URLs, titles, keywords and preferences are preserved; the collector never rewrites `search.yaml`.

* `search.yaml`: the owner's 16 sources, title/keyword OR queries, ranking preferences. Aliases include Node.js/Nodejs, Web3.js/Web3js, Layer 2/L2, CTO/chief technology officer, technical/tech lead and artificial intelligence/AI. Matching is word-aware. No location, compensation, employment-type or old September strategy exclusion silently removes a job. Empty title **and** keyword lists stop collection.
* `candidate.yaml`: relative PDF/Markdown paths and exact external URLs discovered in the existing website/documents. Both PDFs use deterministic Poppler text extraction; no PDF or existing KB content is edited. Optional profile `export` points to an owner-provided relative `.pdf` or text/Markdown file, e.g. `.local/imports/linkedin.pdf`. A configured but missing export is an error, not permission to invent profile text. Public cache lifetime is configurable. **Refresh sources** refreshes remote snapshots explicitly; daily runs reuse fresh cached snapshots.
* `providers.yaml`: provider/model and context/timeout by stage. Assessment uses the selected provider. Default extraction is deterministic structured HTML/RSS/API/PDF extraction; see model extraction below. There is no automatic cross-provider or paid API fallback.
* `network.yaml`: per-source profiles, optional `browser: true` and `proxy_env: FCTO_PROXY_URL`. `sources` keys are exact configured source names (or `profile:linkedin`, etc.). Only an environment-variable **name**, never a proxy credential/value, goes in tracked YAML. HTTP and Chromium use the same selected proxy. No system VPN setting changes. Profiles do not grant access to an unsupported board.
* `runtime.yaml`: port, bounded pages/jobs/requests and daily local hour/minute. The legacy `max_assessments_per_run` remains readable for compatibility but does not cap the persistent worker. Port changes require restarting the server; launchd time changes require regenerating/reloading its reviewed plist on the mini.

`prompts/assessment.md` is editable. Full extracted sources, content hashes, retrieval dates, context version and missing/stale notices are visible in Context. Known contradictory statements are review notes, not silently resolved achievements. FAQ answers remain attributed source text; they are not confirmed universal facts. Candidate feedback and explicit Stage 2 Remember are separate additive writers; ordinary draft edits write no reusable knowledge. Eligibility/invoicing is unresolved, never inferred from citizenship/IP/location. Each successful assessment records model/provider, prompt/context/job hashes, exact supporting quotes and selected/omitted source sizes; quotes absent from the preserved candidate source are rejected. Sources that exceed a model budget fail explicitly instead of silently cutting a CV. Changed facts/context show stale assessments.

**Model extraction:** `runtime.model_extraction: true` opts into a fallback for pages lacking a deterministic description. It uses `stages.extraction`, `prompts/extraction.md` and that provider's budget/timeout. All non-null fields must be exact contiguous quotes from the fetched page; invented text is rejected. Model-selected text is labelled an excerpt with unverified full coverage, including provider/model/prompt/page hashes. Models never supply application URLs. Deterministic extraction remains the default and no model is needed to collect/read supported sources. Both stages can use local inference. PDF extraction remains deterministic Poppler.

## Backup, restore and changing the operational machine

Git carries code, YAML, prompts and existing Markdown/PDF inputs only after the owner explicitly commits them. This implementation performs no commits/pushes. Git **does not** synchronise saved/rejected state, job history, candidate snapshots, assessment records, browser sessions or runtime logs.

```sh

```

This uses SQLite `VACUUM INTO` to make a consistent `.local/backups/jobs-<timestamp>.sqlite`, including committed WAL data and the persistent assessment queue. Back up to an encrypted owner-controlled destination. Do not copy a live `jobs.sqlite` alone while its `-wal`/`-shm` files are active. The database contains private candidate/job data. For a machine transfer, also preserve `.local/network.sqlite` consistently while stopped: it holds request caches and domain cooldowns, which must not be reset simply by restarting on another writer. Candidate feedback Markdown travels with the owner-approved repository state. Sessions are excluded from routine transfers; log in again rather than copying cookies/OAuth credentials.
