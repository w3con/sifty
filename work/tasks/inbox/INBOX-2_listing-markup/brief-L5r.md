## L.5r1 — Fits you band (replaces the Key facts strip and the Quick match cards)

Back end: one place computes the merged facts of a vacancy, in the order structured source fields, then code reading the classified sections, then the model's extracted conditions (quotes validated, as the existing condition-conflict path already does). It returns, for each tile of the active profile's goals (today Money, Location, Work mode, Contract), the value, its origin label and a verdict state ok / not matching / not stated. It is served in the single-vacancy response only (not in the list payload).

- Money: read the range only from Compensation and Benefits sections and from the model's compensation condition (parse the model's string into minimum, maximum, currency, period, tax note). Convert to the profile currency with rates from configuration (hand-edited, no network): a range without a tax note counts as gross; month × 12; hour × 2080; any other period or a currency without a rate is shown but not compared (neutral). Verdict ✓ when the upper bound of the converted range is at least the profile minimum, ✕ otherwise (the existing comparison also uses the upper bound). The tile shows the original range, «≈ €…» and the verdict. The exchange rates and their defaults go into a configuration file with a template; the defaults are placeholders that the coordinator must flag to the owner as not market data.
- The Fits you number must use the same converted comparison, otherwise the tile and the number disagree. Change the compensation comparison in the quick-match evaluator accordingly, feed the model's parsed compensation into it, and let the rules identity change so the stored results are recomputed at startup by the existing mechanism. Check on the owner's example (vacancy with id 950 on a copy: base salary $150,000–$250,000): the tile shows ✓ and the Fits you number's compensation group is no longer "unknown".
- Location: value only, neutral fill, no verdict (no goal exists in the profile yet).
- Work mode: structured field, then the model; text reading only as a weak hint shown after them and marked as a hint, never as a stated value.
- Contract: structured field, the model, or explicit words only (freelance, contractor, contract role/position/basis, permanent role/position, fixed-term contract, W-2, 1099, employment contract); bare full-time / part-time is not a contract value. The word lists live in configuration, not in code.
- Front end: the band is one card: the Fits you number with its bucket pill on the left, one tile per goal on the right (icon, value large, one comparison line, fill by verdict, ✓ / ✕ / ?). It replaces the fact strip and the separate Quick match cards in Overview; keep what those cards did that the owner uses (Refresh, Assess, existing waiting indicators).

## L.5r2 — What they ask / What they offer cards

- What they ask: the model's extracted requirements (record in `match_vacancy_extractions`), whether or not a Requirements section was recognised; groups Required and Nice to have; header with counts ✓ / ✕ / ?; each row has its mark, the requirement text and the evidence quote in small text; ✓ in your profile (code verdict), ✕ in "Skills you do not have", otherwise ? with ✓ / ✕ buttons that use the existing profile endpoints. One line «not found» only when there is no extraction or it is empty; the full listing stays below.
- What they offer: tiles with icons for salary range (from the money tile), equity, benefits, time off and a few further items from a small vocabulary kept in configuration; read from the Compensation and Benefits sections only; each tile shows a stated value or «not stated». When no offer section was recognised the card says so in one line.

## L.5r3 — Full listing open, switch removed

The full listing is shown open, with no Show button and no By section / Original switch; remove the switch, its state and unused styles. Keep the stored sections and their API: the offer card and the classification still read them. Update `docs/MAP.md` and the spec status line.

## Rules

- Live data is never touched: no writes to `data/` or `data-staging/`, copies only, made with `sqlite3 "file:<path>?mode=ro" ".backup <dest>"` into the scratchpad. Ports 8080, 8081 and 8094 are not used; 9199 only for throwaway servers, stopped by PID afterwards. Run copies with `collection_disabled: true` and no model calls.
- Never `make build` or `bin/sift-deploy`; build into the scratchpad. Never merge or push. No sub-agents.
- Tests: only a few targeted ones where the owner cannot see an error in the UI (money parsing and conversion, period conversion, the comparison, contract and offer readers). Four failures exist on main and must stay as they are: `TestMigrationV14`, `TestMigrationV16ToV17PreservesData`, `TestSchema_FreshDatabase`, `TestRouteDrift`.
- No hardcoded values: rates, vocabularies and word lists in configuration with defaults in the templates. Respect the layer split (matchsvc, store, interface).
- After each step: tick the checkpoint in `plan.md`, add a short entry to `log.md`, commit with `../../bin/work-commit INBOX-2 -m "type(INBOX-2): ..."` (one commit per step or finer). Add a migration only if a new table is unavoidable (current version is 27).
