- Сначала сохранить согласованный снимок текущих staging DB/config/profile/source records. Затем подготовить запрошенный владельцем пустой старт только на staging: прежние введённые данные и оригиналы сохраняются в восстановимом снимке. Не удалять production-данные и не копировать production на staging.
- Новый пустой профиль не заполняется legacy-источниками при GET; существующие данные не исчезают при обновлении приложения. Смена старого staging-профиля на пустой — явное одноразовое действие, не скрытый эффект чтения.
- Новые поля, форматирование, календари и уровни языков принадлежат SETTINGS-3; URL — SETTINGS-4; словарь — ASM-5. Здесь нет новой формулы балла, очереди, harness repair или production release.

## Решения

- Сохранять только выбранный раздел атомарным серверным обновлением текущего профиля. Не отправлять устаревший полный профиль поверх других разделов. Черновики остальных разделов сохраняются и не становятся конфликтными из-за чужого раздела.
- Последний явный Save одного и того же раздела заменяет этот раздел; он не заменяет остальные. Сохранение/подтверждение факта остаётся защищённым от поздней публикации анализа. Техническая revision нужна для stale-оценок внутри; на экране нет revision/rebase/discard/history UI.
- Если нормализованные значения не изменились, закрыть редактор без записи, пересчёта и модельного вызова. Cancel относится только к выбранному разделу.
- В пустых Skills/Experience редактор сразу показывает первую строку. Незаполненная добавленная строка не превращается в факт; частично заполненная строка не теряется без сообщения.
- Пустое значение показывать как `Not set`, не как `Unknown` и не как подтверждённое false/0.
- Разделять «текст готов, анализ не запускался», «анализ выполняется», «анализ завершён, фактов нет», «ошибка». Показывать URL существующего remote source, если он сохранён; отсутствие URL не выдавать за известный адрес.
- Ошибки содержат понятную причину и действие: timeout → повторить/проверить выбранную модель; модель недоступна → открыть существующие настройки; missing original без текста → загрузить файл; текст есть → повторная загрузка не нужна. Технические детали доступны отдельно. Успешный старт не остаётся успешным сообщением после ошибки.
- Проверить действительный extraction provider, model, timeout, context/request options и доступность Ollama. Исправлять измеренную причину, не подменять провайдера и не повышать timeout наугад. Одна короткая синтетическая проверка, затем один документ владельца при его действии; никаких циклов cloud fallback или bulk assessment. Не считать наличие процесса Ollama доказательством успешного inference. Если модель остаётся неработоспособной, явно зафиксировать незавершённость этого критерия.
- Производный context/ranking синхронизировать локально с подтверждённым профилем. При сбое дать действие повтора и честный статус; не маскировать ошибку и не запускать LLM.

## Acceptance criteria

- Открыты Skills и Experience: Save первого, затем второго сохраняет оба; несохранённый черновик другого раздела не теряется. Перезагрузка подтверждает результат. Нет сообщений revision/rebase.

- Реальный запуск configured extraction заканчивается фактами либо честно завершённым пустым анализом; timeout не принимается как доказательство работы. Не запрашивать paid provider молча.

- Сборка и реальный браузер подтверждены; broad suites SKIPPED, скрытые инварианты отдельно. Записать фактическое время и результат owner review. Релиз требует отдельного принятия.
