# Приёмка: Select на любой раскладке

## 1. Итог и статус

Обработчик Select использует физическую клавишу KeyY вместо введённого символа. Проверка координатора: принято по diff и сохранённым свидетельствам сборки и браузерной проверки. Принятие владельцем ожидается. Код находится в ветке `work/TRIAGE-2`, реализация `77431e8`; в рамках K.2 принятое исправление перенесено в main текущим коммитом вместе с текущими записями карточки, production не обновлён. Карточка технически готова к review, формальное закрытие не выполнялось.

## 2. Где посмотреть

Исходники: [обработчик клавиатуры](../../../../frontend/main.tsx), строки121–131 в этой рабочей копии. После согласованного переноса в main доступный на staging интерфейс можно проверить: выбрать вакансию в Inbox и нажать физическую Y при английской и русской раскладках; оба нажатия должны выполнять Select. Сейчас изменения доступны только в отдельной рабочей копии; временный проверочный сервер не является пользовательским окружением.

## 3. Что изменилось

Добавлена проверка `e.code === 'KeyY'` и подавление стандартного действия для этой клавиши. Источник входных данных — событие браузера; логика остаётся в существующем обработчике, кнопка и данные приложения не менялись. Условие Select больше не зависит от символа `e.key`.

## 4. Что я проверил

Координатор прочитал фактический diff, вывод сборки и пяти проверок Chromium. Проверены события y/KeyY и н/KeyY, отсутствие Select для y/KeyZ, защита поля ввода и Ctrl+Y. Браузер работал со явно обозначенными искусственными вакансиями и перехватом API; настоящие данные не изменялись. Это проверка событий браузера, а не ручное переключение системной раскладки. Существующие ограничения для модальных окон, модификаторов и композиционного ввода сохранены в коде. Сборка TypeScript/Vite прошла; широкие тесты SKIPPED, а не passed. Независимо проверены метаданные исполнителя: opencode-go/deepseek-v4.1-flash, 53 сообщения помощника на момент проверки.

## 5. Спорные решения и компромиссы

Выбрана согласованная привязка к физической клавише: символ y с другой физической клавиши не вызывает Select. Настройки раскладок и новый слой конфигурации не добавлены.

## 6. Что учесть дальше

Обязательное продолжение для доступности в основном приложении — согласованный перенос исправления в main; выпуск production требует отдельного разрешения. При первой сборке обнаружены неполные зависимости в основном `frontend/node_modules`; исполнитель использовал уже установленные зависимости рабочей копии профиля и успешно собрал интерфейс. Основной каталог зависимостей не исправлен; штатное восстановление — `npm ci`. Других изменений приложения или новых улучшений не назначено.
