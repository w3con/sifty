### 3. Что изменилось
- Ответ модели приводится к нужной форме в коде: простое название навыка становится навыком с уровнем «не указан», массив навыков раскрывается в отдельные записи, «Remote» читается как «remote».
- Для каждого навыка из группы цитатой становится его собственное название, если оно дословно есть в документе. Раньше одна неточная общая цитата отбрасывала все навыки сразу.
- Новое поле «разрешение на работу» и разрешённое для разбора поле «текущее местоположение».
- Правило инструкции: описание прошлой команды или роли не является ограничением кандидата.
- Совпадающее с профилем значение получает состояние «совпадает с профилем» и не показывается как решение. Место работы той же компании с пересекающимся периодом считается уже внесённым.
- Заголовок больше не предлагается из документов и не передаётся в подбор вакансий. Сохранённые значения не изменены.
- Длинный документ делится на части с учётом границ символов, предложения из частей объединяются.

### 5. Спорные решения и компромиссы
- Схема ответа по каждому полю для модели (шаг 1 плана) не сделана: Ollama не умеет выражать «для этого ключа значение такого вида» одной плоской схемой. Вместо неё нормализация в коде. Последствие: надёжность держится на коде, а не на ограничении ответа модели.
- Запрет выдуманных условий (шаг 3) реализован только правилом в инструкции. В прогоне работает, но кодовой проверки нет.
- Объединение «ЕС» как страна: модель может вернуть код «EU», это не код страны по стандарту, но поле его принимает; решение о принятии за владельцем.
- Привязка цитаты к названию навыка слабее общей цитаты: цитата теперь только само слово, а не строка с контекстом. Выбрал это, потому что иначе теряются все навыки, а защита от выдумки сохранена: название должно быть в документе целым словом.
- Исполнитель дважды записал в коммиты фрагменты твоего резюме (инструкция модели, журнал, тесты). Я заменил их выдуманным текстом. Ранние коммиты ветки их ещё содержат; выпуск делает один сводный коммит, и в `main` они не попадут.
