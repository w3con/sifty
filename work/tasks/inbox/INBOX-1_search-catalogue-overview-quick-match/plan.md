# План: профиль → поиск → оценка → Overview

**Состояние:** предложение координатора для обсуждения, исполнение не одобрено.

## Результат и пользователь

Пользователь добавляет свои CV и исправляет единый профиль; его данные меняют предварительное ранжирование всего собранного каталога. Поисковые термины включаются/выключаются без потери сохранённых вакансий и без повторного обращения к сайтам. После Select подробная модельная оценка учитывает полный текст, профиль и произвольные ограничения. Overview показывает факты, причины предварительного балла и отдельно уточнённый результат. Дизайнер получает работающие данные и действия для доработки внешнего вида.

## Решения и авторство

Владелец предложил порядок «с профиля, потом перейти к поиску, затем модуль оценки, затем карточка вакансии». Координатор принимает его в этом предложении. Владелец ответил «ок» на вариант первой версии, в котором свободные пожелания/dealbreakers проверяет LLM после перехода в Preparation, а не универсальный быстрый интерпретатор. Быстрый и уточнённый баллы сохраняются раздельно. Нижеследующие границы этапов, способы извлечения и оценки времени написал координатор; это не уже одобренная реализация.

## Общие границы первой версии

- CV — входной источник для Sifty. Несколько документов питают один профиль. Генерация CV под вакансию, автоотправка файлов/фото и заполнение форм сюда не входят.
- Быстрый расчёт работает без модели; обычные поля/подтверждённые навыки влияют там, где есть определённое сравнение. Свободные пожелания сохраняются дословно и проверяются подробной модельной оценкой в Preparation. Не создавать универсальный конструктор правил и не обещать, что произвольный чип исполняется в Quick Match.
- Полный текст вакансии нужен до нового полного быстрого/модельного расчёта. Пустое/частичное/заблокированное описание — состояние ожидания или ошибки, а не нулевой fit. Обрабатывать весь активный собранный набор, не первые N на экране.
- Источники могут иметь ограниченное покрытие; не обещать скачивание сайта целиком. Приоритет API/выгрузкам, дозагрузка описаний с очередью/ограничениями, сохранение обнаруженного до пользовательских исключений. Не переписывать все адаптеры.
- Для Overview сначала использовать структурированные сведения источника и надёжно извлечённые фрагменты текста. Для отсутствующего факта показывать неизвестность. Не запускать LLM для каждой вакансии ради заполнения всех плашек макета. Если нужен безусловно полный semantic Overview, это отдельное расширение со своей ценой, не скрытая часть плана.
- Импорт CV может отдельно использовать настроенный provider извлечения фактов после явного действия пользователя. Это не Fit Assessment вакансий; стоимость и обработку документа показать явно, не запускать заново при каждой правке поля.
- Общие факты вакансии не смешивать с пользовательскими предпочтениями/оценками. Сейчас один локальный пользователь: не строить аккаунты, размещение сервера или multi-user rollout, но не закреплять пользовательские запреты в общем сборе.
- Сохранять существующие документы, конфиги, историю, данные обоих окружений, незакоммиченный дизайн в main и отдельные worktrees. Production и выпуск — отдельное завершительное решение, не следствие одобрения этого плана.
- Только немного критических targeted tests для скрытых ошибок, которые владелец НЕ способен обнаружить глазами в приложении: сохранность/атомарность данных, гонки, версии, существенные scoring-инварианты и неожиданные модельные вызовы. Не создавать тесты на каждый экран/кнопку/обычное взаимодействие, не расширяться до broad suites/матриц/новой инфраструктуры. Видимый результат проверять сборкой, ревью и реальным браузером/staging; HTTP200 не доказывает отрисовку. Общие suites по умолчанию SKIPPED; full run только по явному запросу, точечные результаты отмечаются отдельно.

| 5. Поиск по умолчанию из профиля — необязательное последующее продолжение | Создать начальные условия, не перезаписывая ручной поиск | Уменьшить первую настройку пользователя | 1+2; по просьбе владельца «потом» | 3 | +30–60 мин, включая его приёмку |

**Основной итог:** 9.5–15.5ч по сумме диапазонов, округлённый бюджет **10–16ч AI** для этапов1–4 с общей подготовкой/приёмкой. Необязательный5 добавляет0.5–1ч и не включён в основной бюджет. Ожидание ответов владельца исключено. Длительные загрузки источников/модельная обработка выделяются отдельно и не должны скрываться под временем написания кода.

Это уточнение прежней ранней оценки7.5–13ч общего обсуждения: теперь учтены несколько документов/DOCX и извлечение фактов, редакторы и сохранение, дозагрузка/состояния описаний, объяснения и проверка реального браузера. Полное слияние двух frontend-копий после детализации исключено из обязательных работ; новые Profile views/hooks работают в основной копии. Этап1 не складывается с прежними5–9ч карточки профиля: это её уточнённый первый объём; расширение общего скоринга вынесено в3, а не посчитано дважды.

**Денежные/внешние расходы:** исполнитель использует существующую подписку OpenCode Go, точная относимая стоимость неизвестна. Модельные вызовы при разборе CV и выбранных вакансий зависят от настроенного provider; без его выбора/тарифа цену нельзя назвать. Новые платные сервисы не планируются; не оценивать весь каталог LLM. На этом этапе планирования ни один такой вызов не выполняется.

Время каждого этапа включает загрузку контекста исполнителем, нужные сборки, ревью и ожидаемые небольшие исправления. Общая подготовка и итоговая проверка учтены отдельно один раз. Верхняя граница каждого запуска — граница остановки с сохранением результата; превышение требует отчёта и новой оценки до продолжения.

Этап1 ведётся отдельной SETTINGS-1; этапы2–4 нужно оформить отдельными ограниченными карточками при подготовке конкретной волны, связав их с этой последовательностью. Один исполнитель получает только один проверяемый шаг/этап, затем координаторское ревью. Новая функциональность не стартует по факту наличия этих checkbox.

## Критерии общей приёмки

- Вся согласованная информация профиля сохраняется и доступна дизайнеру через работающие действия. Документы и примеры макета не подменяются выдуманными фактами.
- CV → подтверждение/исправление навыка → Save действительно меняет ранжирование релевантных вакансий; отмена не меняет сохранённый профиль. Изменения версионируются, старые LLM-результаты не выглядят актуальными.
- Изменение поиска не обращается к сайтам и не удаляет документы/вакансии. Выключенный термин остаётся; при всех отключённых условиях нет скрытого возврата к старым правилам.
- Для всего активного собранного набора известны состояния описания и быстрого расчёта. Неизвестный fit не равен0; полнота каталога не выдаётся за полноту всего сайта.
- Select ставит подробную оценку в очередь только при подходящей стадии/полном описании; свободный dealbreaker проверяется с доказательством либо unknown. Ошибка/выключенный provider не подменяют быстрый балл и не означают успешную оценку.
- Overview показывает реальные известные факты и источники, отдельно предварительный и уточнённый баллы. Пользователь может перейти к Profile/«I know this», сохранить уточнение и увидеть пересчёт.
- Сохранены текущие данные, корректировки, документы, дизайн и production. Нет автоматической генерации/отправки CV и массового платного scoring до triage.
- После каждого этапа владелец получает отчёт по установленному шаблону с прямыми ссылками на фактический код/экран и текущим состоянием интеграции. Build/реальная браузерная проверка не заменяются HTTP-пингом; paused suites честно SKIPPED.

## Что уточнить до запуска соответствующего этапа

- До1: принять базовый функциональный объём и выбрать/подтвердить provider и лимит для извлечения фактов из CV. При отсутствии модели экран должен честно сохранять файл/текст и ручные факты, не обещать автоматический анализ.
- До1.1: подтвердить основной frontend как рабочую основу; новый Profile сразу разделить на views/hooks. Полное слияние DESIGN-2 не блокирует профиль и требует отдельного назначения; не переписывать историю и не включать production release по умолчанию.
- До3.1: формула весов, обязательное/желательное/unknown и стабильность шкалы; конкретные значения нельзя брать из демонстрационного макета.
- До4: подтвердить границу первой версии Overview — надёжно извлечённые факты с неизвестностями, без обязательного LLM на весь каталог.
- Выбор/одобрение плана в чате записывается на диск; до него допускается только подготовка карточек, не реализация.
