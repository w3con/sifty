### 3. Что изменилось
- Web3 Careers: обнаружение вакансий берёт ссылки на страницы вакансий (раньше возвращался адрес главной страницы); описание берётся только из блока описания, без шапки страницы и кнопок «Apply», «Join talent pool». Причина первой ошибки: в разметке страницы между двумя атрибутами нет пробела, и парсер отбрасывает класс, по которому блок искали; выбран другой, устойчивый класс блока.
- Remote3: обнаружение идёт по ленте RSS сайта, а не по странице (в ней нет ссылок на вакансии), описание берётся из блока страницы вакансии. Раньше все 40 описаний были текстом страницы категории.
- We Work Remotely: описание берётся из ленты RSS (в ней разметка с заголовками и списками); для страниц оставлен выбор блока содержимого без шапки страницы.
- Страницы, закрытые Cloudflare (ответ 403), не запрашиваются повторно: один запрос и пауза.
- Конвертер: текст верхнего уровня без блочного тега оборачивается в абзац.
- В настройках адрес Web3 Careers исправлен на `https://web3.career`.

### 4. Что я проверил
- Подтверждено: тесты пакетов collect, source, background и fetch проходят без кэша, включая тесты на каждый из трёх адаптеров, на запрет повтора при Cloudflare и на абзац верхнего уровня.
- Подтверждено на временной базе после живого сбора Web3 Careers (16 вакансий): фраза «Join talent pool» встречается в 0 строк (до исправления — во всех 16); у всех 16 `description_html` начинается с допустимого тега; сырых тегов и двойного кодирования нет; апострофы на месте, например «CleanSpark's vehicle insurance policy», «You'll be the second person in BCB's data function».
- Подтверждено: сервер на порту 9199, оставшийся от прежнего проверочного сбора, я остановил сам; на 9299 сервера нет; каталог `data-staging` не менялся; серверы на 8080, 8081 и 8094 не тронуты.
- Подтверждено: падения в store (миграция версии 14, перенос с версии 16 на 17, свежая база) совпадают с `main`.
- Не проверено вживую: сбор по Remote3 и We Work Remotely в базу. Для них есть тесты на реальных сохранённых страницах (Remote3: лента и страница вакансии; We Work Remotely: лента) и больше ничего. Страница тела We Work Remotely в тестах написана вручную, потому что реальные страницы закрыты Cloudflare.
- Не проверено: тест расхождения маршрутов в server (известное падение на `main`), в этот раз заново не запускался.
- Ограничения результата: в конце описания Web3 Careers остаётся строка «Apply Now:» (слово есть у 15 из 16 строк; у остальных это текст самой вакансии); у одной вакансии `description_html` начинается с пустого абзаца.

### 5. Спорные решения и компромиссы
- Исполнитель заменил способ обнаружения вакансий Remote3 с страницы на ленту RSS. Это шире формулировки плана («взять страницу вакансии»), но страница не содержит ссылок на вакансии, поэтому иначе обнаружение не работало. Последствие: адаптер зависит от адреса ленты сайта.
- Первая версия живой проверки Web3 Careers была ложно оптимистичной: исполнитель назвал текст шапки страницы ожидаемым поведением. Дефект нашла проверка координатора по данным в базе; после исправления исполнитель сам нашёл корневую причину.
- Сохранённая страница Web3 Careers для теста и ленты других адаптеров заменены реальными по моему требованию; на это ушло около 35 минут сверх оценки шага.
- По вопросу тестов владелец спросил, нужны ли они на этапе прототипа; ответа до завершения работы не было, поэтому шаг выполнен по плану, с тестами на исправление.
